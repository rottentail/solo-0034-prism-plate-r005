# 棱版合成调度评估：逐采样点求值 / 整层离屏合成 / 分区缓冲

日期：2026-11-18。评估对象：`internal/raster`（生产 PNG 渲染）、`internal/paint`（线性光合成）、`internal/vector`（SVG 校样）。约束：单工作者浮点中间缓冲 ≤ 8MiB；稀疏大画布不得按整幅分配；不改变生产合成规则；不把逐形状透明度当作组透明度的等价替代。

实验代码在 `analysis/exp/`（仅导入生产包，不修改任何生产文件）。复现：

```sh
go run ./analysis/exp -mode verify    # 字节级等价验证（10 场景 × 13 变体）
go run ./analysis/exp -mode measure   # 计算/分配/边界成本
go run ./analysis/exp -mode memory    # 8MiB 预算推算表
go run ./analysis/exp -mode counter   # 组边界反例（数值）
go run ./analysis/exp -mode e2e -http-png <file>  # 与在役 HTTP 服务对拍
```

环境 linux/arm64, go1.24.9；绝对耗时与机器相关，相对比较有效。

## 1. 生产语义（从代码读取）

`raster.Render`（internal/raster/raster.go:15-57）对每个像素取 2×2 子采样；每个采样点：`dst=背景`；按层升序：裁域/蒙版 `Contains` 不通过则跳过该层；层内各形状以 `normal` 叠入 `src`；然后 `dst = Over(dst, src.Scale(不透明度), 混合方式)`（raster.go:42）——**组透明度与混合方式对整层聚合结果恰好施加一次**。四个子采样平均后量化。

`paint.Over`（paint.go:53-66）：`normal/multiply/screen`；当 `src.A==0` 或 `dst.A==0` 时退化为 normal 公式。`geom.Contains`（geom.go:77-100）：半开边规则 + 严格 `x > p.X`，逐点 O(边数)。准入预算 `Segments×W×H×4 ≤ 1.6×10⁸`（validate.go:174）正是逐采样点求值的边遍历上限。SVG 导出用 `<g opacity>` + `mix-blend-mode` + `isolation:isolate`（vector.go:58）表达**组级**语义。

## 2. 等价条件（独立推导，全部经字节级验证）

- **E1 逐采样点独立**：每个采样的合成只依赖该点的场景状态，采样间无共享状态 ⇒ 对 (x, y, 子采样) 域的任意空间划分与遍历顺序安全，前提是保持每采样点内的操作序。这是分区缓冲合法性的根。
- **E2 层组原子性**：层内形状只能以 `normal` Over 聚合；`Scale(α)` 与混合方式必须对聚合结果施加恰好一次。缓冲拆分只允许发生在该施加**点之下**（部分和按原序以 normal Over 合并）；把 α 或混合方式逐形状施加**不等价**（§6 数值反例），且会与 SVG 的组语义矛盾。
- **E3 恒等捷径（位精确）**：(a) `src=0` ⇒ `Over(dst, 0, mode)=dst`（paint.go:55 走 normal 分支，`0+d×1=d` 精确成立）；(b) `α=0` ⇒ 整层恒等；(c) 裁域/蒙版/形状的包围盒与区域不相交 ⇒ 覆盖必为假 ⇒ 恒等。三者共同许可剔除与空块直填背景，不改变任何输出位。
- **E4 覆盖判定等价**：跨度转换必须复用同一半开边规则与同一浮点表达式 `a.X+(p.Y−a.Y)(b.X−a.X)/(b.Y−a.Y)` 及严格 `x>p.X`。裁域/蒙版本就在画布坐标，跨度化**可证位精确**；形状跨度需把路径预变换到画布空间——数学上等价（仿射双射保持 winding≠0 与奇偶性），在全部 10 个测试场景上位精确，但对"采样点恰好落在变换后边上"的对抗输入不可证 ⇒ 需要验证门或回退（§7）。
- **E5 浮点序**：位一致要求每采样点操作序一致（层升序、形状升序、÷4 后按 (sx,sy) 序求和）。normal Over 在数学上可结合（预乘），重分组视觉安全但非位安全——仅当要求跨渲染器版本的摘要稳定时才有影响。

## 3. 三种策略的适用边界

实现：S0=逐采样点（生产克隆，插桩）；S1=整层离屏（样本分辨率 dst+src 双缓冲）；S2=分区逐采样+包围盒剔除（零额外内存）；S3=分区缓冲+扫描线跨度（含裁域/蒙版每行一次跨度）；S3h=S3+实色笔刷提升。验证：10 场景（覆盖率 0.4%–91.2%）× 13 变体 PNG 字节与生产 `raster.Render` 全等；并经在役 HTTP 服务对拍（amber 成品摘要 `f1004dd8…` 三方一致）。

### 3.1 内存边界（硬约束，float64 RGBA=32B，样本网格 2W×2H）

| 策略 | 中间缓冲 | 合法条件 | 512×512 时 |
|---|---|---|---|
| S0/S2 | 0 | 恒合法 | 0 |
| S1 整层离屏 | 256·W·H 字节（dst+src） | **W·H ≤ 32768**（128×256 恰好 8MiB） | 64MiB，**超 8 倍** |
| S3 分区缓冲 t×t | 256·t² 字节 + 侧缓冲 | **t ≤ 181**；见 §3.3 侧缓冲联合约束 | t=128 → 4.06MiB |

S1 在 256×256 需 16MiB、512×512 需 64MiB，直接出局；只有 ≤128×256 的小画布合法。稀疏大画布为少量形状分配整幅图层正是 S1 的结构性缺陷，与约束直接冲突。

### 3.2 计算与实测（min-of-5，ms；edge=边循环迭代，samples=笔刷求值，overs=合成次数）

| 场景（覆盖率） | S0 | S1 | S2@64 | S3@128 | S3h@128 | S0→S3h |
|---|---|---|---|---|---|---|
| amber 192×144 真实样张 (44.4%) | 33.4 | 24.0 | 34.8 | 16.8 | **14.8** | 2.3× |
| sparse 512² (0.4%) | 217 | 79 | 148 | 42.4 | **40.9** | 5.3× |
| cover10 512² (9.9%) | 790 | 634 | 218 | 56.0 | **43.9** | 18× |
| cover50 512² (50.8%) | 860 | 714 | 286 | 113 | **50.3** | 17× |
| cover90 512² (91.2%) | 915 | 768 | 353 | 168 | **55.6** | 16× |
| dense-stack 512² 24 形叠 3 层 (57.9%) | 2433 | 2254 | 2370 | 1792 | **1254** | 1.9× |
| boundary 512² 16 长条跨界 (24.8%) | 498 | 363 | 376 | 95.0 | **65.0** | 7.7× |
| evenodd+裁域+蒙版 256² (36.6%) | 73.9 | 46.5 | 77.4 | 38.2 | **30.4** | 2.4× |
| small 128² (48.6%) | 23.3 | 15.2 | 23.8 | 11.3 | **7.7** | 3.0× |
| tall 128×256 (37.5%) | 33.0 | 17.0 | 32.1 | 11.6 | **5.9** | 5.6× |

关键读数：

- **S0 的边迭代 = Segments×4WH**，与准入预算同式（cover 场景 144×512×512×4=150,994,944，实测吻合）。预算即 S0 的最坏成本模型，对 S3 是保守上界，无需改动。
- **S1 计算量与 S0 完全相同**（edge/samples 逐项相等），墙钟快 7–64%（sparse 场景达 2.7×）仅来自背景色 `paint.From` 提升出采样循环（S0 每采样 3 次 `math.Pow`）与紧致循环——这部分收益任何策略都可免费获得，不是离屏本身的功劳。
- **S2 零内存**，收益随稀疏度放大（sparse 边迭代 8.4M→0.39M；cover10 151M→4.7M@t64），密集重叠时退化为 S0（dense-stack 89.8M vs 100.7M，墙钟持平）；小画布上因块管理开销略慢 2–4%。
- **S3 边工作坍缩**（dense 100M→0.32M；boundary 67M→0.16M；cover90 151M→0.036M），全部场景净胜；`contains` 归零。
- **密集透明重叠的下限**：samples+overs 是不可约的真实合成工作（dense-stack 各策略均为 9.83M 笔刷求值、11.3M 合成）。缓冲只能消除覆盖判定的重复计算，不能减少混合算术；S3h 的实色提升（samples 9.83M→4.92M，gradient 不可提升）把 1.36× 抬到 1.94×，渐变密集型密集重叠本质上是计算瓶颈而非调度失败。

### 3.3 边界成本与侧缓冲联合约束

块边界上的形状按块重算跨度：boundary-512 的 S3 边迭代 t=160→32 为 151K→505K（≈周长代价），仍低于 S0 三个数量级；墙钟 93→107ms。t 越大边界重算越少，但缓冲越大。

侧缓冲：画布空间路径缓存 ≤ Segments×32B，跨度缓冲 ≤ 单路径段数×16B（结构上 ≤6144 段 ⇒ ≤96KiB）。Segments 受准入约束 `≤ min(3.1×10⁶, 1.6×10⁸/(4·W·H))`：

| 条件 | 结论 |
|---|---|
| **W·H ≥ 611** | Segments ≤ 64K ⇒ S3@128 总量 ≤ 4.06+2.0+0.1 ≈ **6.2MiB ✓ 恒安全** |
| W·H ≥ 739 | Segments ≤ 54K ⇒ S3@160 ≤ 7.6MiB 才安全；否则 t=160 超支 |
| W·H < 611（小画布） | Segments 可到 3.1×10⁶ ⇒ S3 路径缓存最坏 96MiB，**须按 Segments 门控或改用 S1/S2** |
| W·H ≤ 32768 | S1 合法（恰 8MiB 于 32768） |

**结论：t=128 是唯一对全部合法画布（W·H≥611）都安全的块尺寸；t=160 仅在 W·H≥739 时安全；t=181 虽账面 ≤8MiB 但侧缓冲无余量，不采用。**

## 4. 组透明度 × multiply/screen × 背景的相互制约（含数值反例）

三者经 `dst` 耦合：混合模式读取含背景与下层的 `dst`；组透明度在混合**前**对整层聚合缩放（raster.go:42 先 `Scale` 后 `Over`）。`paint.Over` 的 multiply/screen 分支非线性 ⇒ 不可分配到形状级。数值反例（两 α=0.6 形状重叠区，组 α=0.5，背景 0.2 灰）：

| 模式 | 组语义（正确，PNG 与 SVG 共同表达） | 逐形状透明度 | 逐形状混合 |
|---|---|---|---|
| normal | [87 83 139] | [107 83 139] ΔR=20 | [110 105 185] |
| multiply | [41 40 46] | [39 36 41] | [26 21 29] |
| screen | [92 89 141] | [127 91 142] ΔR=35 | [167 116 188] |

SVG 侧 `<g opacity>` + `mix-blend-mode` + `isolation:isolate` 已是组语义；PNG 侧若按形状拆缓冲并逐形状施加透明度/混合，两格式将表达不同的交叠结果（上表 Δ 最大 35/255，肉眼可见）。**因此缓冲拆分的唯一合法位置在层的单次 Scale+blend 点之下**（E2）；逐形状透明度不是等价替代，本评估未采用、生产规则未改动。

## 5. 调度建议（有条件）

1. **默认**：S3@128，每工作者常驻 dst+src+active 三块（4.06MiB）+ 跨度切片，两工作者合计 ≈8.1MiB 常驻 + ≤2MiB 路径缓存。适用条件 W·H ≥ 611（全部实际画布）；前置校验 Segments ≤ 65536（该条件下自动成立）。
2. **小画布 W·H < 611**：S1（W·H ≤ 32768 时合法）或 S2；此时绝对耗时 <25ms，简化优先。
3. **内存收紧 < 4MiB/工作者**：t=64（1.02MiB），保留绝大部分收益（boundary-512：98ms vs t=128 的 95ms）。
4. **零风险路径**：S2@64 剔除（零缓冲、可证位精确、无等价性门槛），稀疏场景 1.5–3.6×；小画布上可能慢 2–4%，按画布面积 ≥256² 门控启用。
5. **免费提升（位精确、纯函数）**：背景色 `paint.From` 每渲染一次；实色笔刷每形状每渲染一次（S3h 已量化：dense 1.36×→1.94×，cover 再快 2–3×）。不改变合成规则。
6. **取消粒度**：S0 按行检查 ctx；S2/S3 按块检查，粒度相当或更细；30s 异步超时与 2 计算名额不变。
7. **不采用 S1 作为生产路径**：大画布超支、小画布被 S3 支配（同合法区间内 S3 均快 1.3–1.5×，见 small/tall/amber 行），仅保留为概念基线。

## 6. 复用建议

- 缓冲按**工作者**分配并跨块/层/渲染复用（S3 每渲染仅一次分配；实测 allocBytes 主要来自一次性路径缓存）。
- 跨度切片按需增长到最大单路径段数后稳定复用。
- 画布空间路径缓存按渲染构建（≤2MiB，受 §3.3 门控）；如需跨渲染复用，可与编译后场景一并按稿本摘要缓存——`validate.Compile` 为纯函数，缓存安全，但准入必须已执行过一次（`service.render` 目前每渲染重编译，service.go:119）。
- 实色笔刷像素、背景像素：每渲染常量，提升到位精确。

## 7. 失败时的有条件建议

- **缓冲分配失败/内存压力**：回退 S2（零缓冲）或 S0；渲染不失败，仅变慢。禁止提交半成品（与现有成品提交点语义一致）。
- **S3 等价性风险**（E4：对抗性边上采样点不可证位精确）：若要求跨版本摘要稳定，采用以下之一——(a) 只用 S2；(b) S3 配验证门：每场景首渲染时与 S2 对拍摘要，不一致则永久回退 S2（每场景一次性成本）。本次 10 场景×4 块尺寸全部位一致，含旋转/渐变/evenodd/裁域蒙版。
- **小画布高段数**（W·H<611 且 Segments>65536）：S3 路径缓存可超 8MiB ⇒ 门控拒绝 S3，走 S1（若 W·H≤32768）或 S2。
- **超时风险**：dense-stack 类渐变密集场景在 S3 下仍需 ~1.3s（512² 上限附近）；30s 异步上限对准入内全部场景有余量（最坏 S0 路径 1.6×10⁸ 边遍历 ≈ 秒级），无需调整。

## 8. 声明

- 生产代码零改动；`internal/raster` 的逐采样点求值仍是权威路径。本评估的全部替代策略仅在实验目录内实现并与生产对拍。
- 未把逐形状透明度/逐形状混合当作组语义的等价替代（§4 反例）；缓冲拆分始终位于层的单次 Scale+blend 点之下。
- SVG 不承诺逐像素一致（README），本评估的一致性结论是：合法拆分下 PNG 与 SVG 表达**同一**组级交叠语义；非法拆分会使两者表达不同结果。
